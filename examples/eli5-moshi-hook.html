ELI5 · 五次接力

Moshi Hook 是怎么向手机打招呼的？

它不是抢走 Agent 的方向盘，而是在关键时刻，把一张“发生了什么”的小纸条递到手机边。

01 · 事件

Agent 先走到一个生命周期节点

任务开始、需要关注或完成时，会出现一个可被观察的事件。这里先有“发生”，还没有手机通知。

Agent lifecycle event
02 · 本地接住

Hook 在 Agent 旁边接住事件

Hook 是本地交接点：它关注事件，并把适合通知的信息交给 Moshi。它不是手机，也不替 Agent 决策。

local Hook
03 · 传递层

Moshi 本地 daemon / Gateway 接过纸条

这一层把本地交接变成 Moshi 可送达的访问与通知路径。它负责“怎么抵达”，不负责“任务接下来该做什么”。

local daemon / Gateway
04 · 配对送达

路径认得那台已经配对的手机

Moshi 沿已建立的配对关系，把通知送向对应手机。图里只表达“有配对目标”，不承诺实时或必达。

paired phone delivery
05 · 手机入口

手机用三个入口，让你看见同一件事

Inbox 适合回看，Live Activity 适合扫一眼状态，Chat View 适合继续交流。Moshi 打开入口；任务与会话的权威仍在 Herdr。

access layer ≠ session authority

这张图故意简化了什么？

箭头只表示概念上的责任交接，不是协议图。daemon 与 Gateway 被合并成一个教学场景；配对、身份、传输、重试、系统通知权限与时序细节均未展开。页面不声称实时、必达或某种加密实现。唯一必须保留的边界是：Herdr 是任务／会话权威；Moshi 是访问与通知层。
