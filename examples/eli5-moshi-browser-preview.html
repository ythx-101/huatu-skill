ELI5 · BROWSER PREVIEW

紫色按钮不是魔法：Moshi 怎么找到并打开本地 HTML？

先有一盏本地端口灯亮起，Moshi 才能把它变成手机里的预览入口。

01 · 先开灯

HTML 要先被本地服务器端出来

Mac 上的应用或服务器必须已经监听一个符合条件的回环 HTTP 端口。Moshi 不会打开裸文件，也不会替你生成 HTML。

先有 server，后有 preview
02 · 手机发问

手机通过 SSH preflight 问 Mac

Moshi 客户端用 SSH exec / preflight 运行指定主机命令 moshi-hook servers。这是拉取式检查，不要求主机配对，也不需要 bearer token。

pull-only host inspection
03 · 扫描与筛选

很多监听者，只留下可展示网页

命令发现符合 scan-ports 策略的回环监听者并逐个探测；只有返回 text/html 或 application/xhtml+xml 的服务会浮上来。

端口策略 → 探测 → HTML
04 · 变成入口

紫色按钮，其实是一张服务器卡片

通过筛选的 web server 被呈现为 Browser Preview 入口。它代表“这里有一个可打开的服务器”，不是让手机任意翻看 Mac 磁盘。

surfaced server ≠ disk browser
05 · 点击后过隧道

同一个端口，从 Mac 接到 iPhone

点击后，客户端建立同端口 SSH 本地转发：phone:<port> → host:<port>，再让 WebView 加载 http://localhost:<port>。

same port · no URL rewrite

简化边界

以上五幅都是概念图，不是线级协议规范。箭头只表示“发现、呈现、转发”的责任与方向；省略了监听器枚举方式、探测时序、SSH 握手、WebView 生命周期、容器归属解析和错误 UI。图中不承诺发现每个服务、实时刷新、端口冲突自动恢复，也不表示服务被开放给局域网或互联网。
