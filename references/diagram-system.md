# 轮播图表示意系统

本参考用于 1080 宽轮播中的机制图与关系图。图表不是正文的插图版：它必须让读者更快看见方向、差异、先后或层级。

## 先判断要不要画

**最高原则：不机械套模板。** 内容决定结构，结构决定模板；模板是候选不是默认。内容被迫适配现成节点数时，删除、合并或重排节点，保留关系本身。任何「先挑模板再塞内容」的流程都违背本系统。

**一句话测试：段落是否比图教得少？是，就画；否，就保留段落。**

图必须增加至少一个维度：**流程、对比、趋势或分层**。只把名词装进方框、给正文配技术感背景、重复标题结论，都属于装饰性图，禁止使用。

## 图表选择

| 要说明的关系 | 首选图表 | 适用问题 | 不该使用时 |
| --- | --- | --- | --- |
| 条件、分支、合流、返工 | `flowchart` | “满足条件后走哪条路径？” | 只有一条无分支直线 |
| 固定顺序、阶段交接 | `steps-flow` | “从第一步到完成如何推进？” | 步骤没有先后依赖 |
| 系统边界、上下层依赖 | `architecture-layer` | “哪一层依赖哪一层？” | 只是在罗列模块 |
| 时间变化、里程碑、阶段转折 | `timeline` | “何时发生了什么变化？” | 时间不是论点的一部分 |
| 双变量定位、优先级判断 | `quadrant` | “对象在两个轴上分别处于哪里？” | 轴没有清晰高低含义 |
| 两种方案的对应差异 | `split-compare` | “同一维度下两边如何不同？” | 三列以上或表格更易扫描 |

## 复杂度预算（默认参考，不是硬法规）

下表是默认预算，帮助模板与正文保持一致；**内容关系需要时可以偏离**，但偏离要在 manifest 里写一句理由（例如「此节点是唯一焦点，宽度升到 176」）。预算合规永远低于「读者是否更快看懂」。

| 项目 | 预算 | 使用方式 |
| --- | --- | --- |
| 节点 | 单图不超过 9 个 | 超出时拆图或合并同行节点 |
| 焦点 | 1–2 个 | 只有焦点使用 brand 描边或 brand-tint 填充 |
| 节点宽度 | 128 / 144 / 160 | 不为某一句话临时扩宽；先缩短文字 |
| 节点高度 | 32 / 64 | 32 用于短标签，64 用于标题加一行说明 |
| 字号 | 手机 1× 可读为准 | 模板内 7/9/12 是 SVG 小尺寸参考档，不是唯一允许值；渲染后主标签约 18–24px、补充约 12–16px；禁止为塞字压到不可读 |
| 坐标与关键间距 | 4 的倍数 | 节点、转折点、轴线与主要留白统一对齐 |

节点内只放短标签、名称和至多一行补充。需要完整句子的解释应放在轮播正文或图下注释，而不是压进节点。

## 视觉 tokens

与 `kami-design.md` 的默认主题保持一致。SVG 的填充与描边只用 solid hex；禁止 `rgba()` 填充、渐变和新增状态色。

| Token | Hex | 图表职责 |
| --- | --- | --- |
| parchment | `#f5f4ed` | 画布 |
| ivory | `#faf9f5` | 普通节点 |
| near-black | `#141413` | 主文字、普通节点描边 |
| olive | `#504e49` | 连接线、次级文字 |
| stone | `#6b6a64` | 标签、弱化信息 |
| brand | `#1B365D` | 唯一强调色，限焦点与主路径 |
| brand-tint | `#EEF2F7` | 焦点节点浅底 |
| border | `#E8E6DC` / `#E5E3D8` | 分隔线、区域边界 |

## 线纪律

- 主流程使用水平、垂直与 90° 转折；不要用随意曲线。
- 箭头使用两笔开口 chevron，不使用实心三角或厚重 marker。
- 轴线或连接线从节点边缘出发，箭头尖端落在目标节点边缘。
- 先布节点再走线；任何连接线都不得穿过文字。
- 分支标签放在线段旁的留白区；必须压在线上时，先以画布色遮住线再放字。
- 非核心关系优先写成图下注释，避免用更多交叉线补充。

## 防 AI-slop 检查表

| 检查 | 失败表现 | 修正 |
| --- | --- | --- |
| 1. 图有教学增量 | 图只是复述标题 | 补上流程、对比、趋势或分层，否则删图 |
| 2. 焦点克制 | 多数节点都用墨蓝 | 只保留 1–2 个焦点 |
| 3. 尺寸成体系 | 每个节点宽度都不同 | 收敛到 128 / 144 / 160 |
| 4. 层级可见 | 所有节点同权同形 | 用位置、尺寸档与一个焦点建立主次 |
| 5. 连线可追踪 | 曲线、斜线或交叉线过多 | 改成正交路径，必要时拆图 |
| 6. 箭头贴边 | 箭头悬浮在节点附近 | 将尖端精确落到目标边缘 |
| 7. 文字不被穿越 | 线从标签或节点文字下经过 | 改路由或给行内标签留遮罩 |
| 8. 不用实心箭头 | 大三角制造 UI 感 | 改为轻量开口 chevron |
| 9. 不靠发光显技术 | 霓虹、渐变、玻璃质感 | 回到暖纸、暖灰与单一墨蓝 |
| 10. 不放装饰图标 | 星星、机器人、无语义符号 | 删除；只有能区分类别的图标才保留 |
| 11. 节点不写段落 | 方框里塞完整论述 | 压缩成标签，把论述移出图 |
| 12. 为塞字压到不可读 | 字号小到手机 1× 看不清 | 禁止压到不可读；允许按渲染目标放大，7/9/12 仅作模板内默认档（见预算表） |
| 13. 不堆重复图例 | 图例解释显而易见的形状 | 直接标注或删除图例 |
| 14. 不用竖排说明 | 旋转文字增加阅读成本 | 改为轴端短标签或水平注释 |

## 示意图表达关系

wafer 参考流程的价值不在外观，而在它同时呈现了三类机制结构：

1. **分支**把判断条件与不同后果放在同一视野中，读者能看见“为何改道”。
2. **并行**把同时发生的处理与单线顺序区分开，读者能看见吞吐或协作方式。
3. **回环**把“下一轮”连接回前序状态，读者能看见系统如何迭代，而不是误以为流程一次结束。

这三种结构分别增加条件、并发和状态演进三个维度。机制型内容不必每次同时使用三者，但必须至少让一种关系变得比文字更清楚。禁止只用箭头、方框或抽象纹理营造“复杂系统”的气氛。

## 接入 huatu 工作流

知识型、机制型和研究型内容在 `mixed` 或 `image-led` 模式下，优先把 diagram 规划为 `visualAnchor`。建议流程：

1. 在 storyboard 中先写清该页要教会的关系。
2. 通过一句话测试，再从六种模板中选择结构。
3. 复制 `assets/diagrams/` 中的 SVG，改写 `DATA START` 与 `DATA END` 之间的占位内容。
4. 在 spec 中用 `image` 块引用 SVG，并为它填写语义明确的 `alt`、`role`、`fit` 与 `treatment`。
5. 渲染后按手机尺寸检查：一秒内能否看见入口、焦点与阅读方向；若必须先读完旁文才懂图，visualAnchor 尚未成立。

diagram 通常承担 `hero`、`evidence` 或 `motif` 角色。它不能以“好看”为唯一理由进入 deck，也不能取代来源、限制条件与正文判断。
